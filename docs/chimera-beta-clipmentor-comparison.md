# Chimera 内测经验与 ClipMentor 对照

2026-11-27。ClipMentor 代码基线为 `0be9bb97`（PR #62）。另核对了当前工作树的网页文案提交 `5d05bf61`，本报告的流程判断以已合入的代码为准。

## 决策摘要

最先值得做的是把**旧内测中肉眼能看出的问题**变成 ClipMentor 的验收样本。首份可审预览要用实际成片核对声音、字幕、讲解画面和两个片尾。计划、时间线和审核回执各能证明其中一部分。沿用现有成片复核与人审入口即可，具体见 M01–M04。

第二项是把“已经保存”和“还在传输”分清。ClipMentor 已能找回提交成功但响应丢失的四份素材，也有真实的本地五任务调度。已证实的差距在首次上传未提交时的恢复，以及不同阶段的下一步在网页上是否一眼可辨。先验这些实际落点，再考虑分片或多进程，见 M08、M09、M13、M14。

现有的版本绑定、正式下载门槛、意见作用范围和已确认内容保护值得保留。Chimera 的原型提供了交互参考。旧表中的工程修复记录大多仍待验收，不能据此认定旧产品已经解决真实复核、付费重试、共享正文或多用户并行。

### 落地顺序

1. **先做输出样本验收。** 从可复用的已存成片和检查事实起步，挑出缺字、锚点漂移、同段判断和双片尾混绑四类反例，各配合法对照。在现有的发布验收和离线回归入口跑同一组样本，所需新渲染或真机听看单独列出。技术上可记录每次素材确认后首份可审预览的等待时长、人工介入、已保存结果复用和重做次数；内容验收由编辑实际看片，确认首版的三项事实：达人一眼读懂拍法和效果、回看兑现口播、两个片尾各自正确。把自动检查通过和人工认可分别记录。
2. **再验恢复与页面行动。** 把同一次上传的首传失败、已保存后丢响应，同一次复核的回执无效、原请求未知及有效整改分别重放。用同一工作台同时显示待审、待复核和可下载输出，检查解释、动作与后台一致。连续失败的恢复先看原操作与已存成片。
3. **按实测决定扩容。** 先量本地五任务的上传峰值、排队时间、首份可审预览耗时和预览页响应；开放多用户或部署多个进程后，再验证额度一致性、账号隔离与故障恢复。允许相同素材参与不同合法任务，不采用旧产品的素材时长、格式政策或全局重试次数作为默认值。
