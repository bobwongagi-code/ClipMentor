## 事实源与完成含义

- `ProductionTask` 及持久运行检查点是制作控制依据。派发时的内存快照不能覆盖执行所有者读到的新检查点。返修要同时保存目标阶段及失效的后续检查点。已登记的最新检查点不可读、正文与索引不符或协议身份错误时，不能退回旧检查点。等时间戳按索引中的发布先后排序，读取与历史压缩共用同一实现。
- 运行索引的排队写入不代表读取版本仍然有效。普通写入必须匹配 `expectedRevision` 并推进一次；set/merge 合入有效变化也推进版本，无变化重放不推进。竞争后仅由现有本地重读接续，不授予外部重试。
- Agent 冷恢复的未知工具结果必须与最后的结束事件按递增编号一起落盘，不能临时插在旧结束事件前。原日志不改写，回放只以最后一个有效结束事件终止。恢复提交同时绑定会话代次及该运行的持久事件尾序号；上下文、待取消审批和恢复后缀原子发布，争用只重读，不重新派发工具。
- 外部调用台账与 raw 文件是“已发出／已收到”的依据。源观察、独立审核及 ASR 的本地回读可接续已保存 raw，不重新发送；缺失、错配、损坏或结果未知仍不算成功。原失败、预算和审核原判不因此重置。
- 共享主体的本地准备许可绑定前后工程字节、生产者、原审核与共用主体。仅允许完成相同的部分提交；遇到后续编辑拒绝。当前任务的额度仍是唯一授权来源，许可不复制额度。片尾仍独立，正式审核仍必须通过。
- 生成任务初始化只恢复本地读取失败，不重跑失败的外部恢复阶段；不认识的账本协议/行或重复ID不能按空账本覆盖。执行结束关闭旧回调权限；清理在引用检查、持久删除及文件回收期间排他，同ID不能同时恢复/重用。过期定时器须同时匹配任务对象和当前timer句柄；提交失败先保留文件，后恢复记录，不能制造指向已删除结果的成功记录。
- 检查点等时间戳不能把导入到达顺序当任务进度；按经原索引/正文核验的 sequence 排序。并发压缩只可从当前已索引的无损归档取回同一记录，不能借较早检查点减少已用次数。网关诊断复用同一历史归档，不能耗尽进度保存槽；已确认的远端 lease 释放只清本地相同 token。
- 工程、运行索引、产物文件的提交边界不同。丢失确认时先回读权威索引；不能把已发布的产物当垃圾删除。通知和提交后的清理失败不撤销成功写入。
- 素材回执核对当前四槽的真实文件哈希，并在异步核验后重读工程版本；文件存在不等于登记内容仍有效。尚未制作的工程可用同名称、同类型、同哈希输入修复缺失或坏文件，保留资产 ID 和有效槽位；旧对象不覆盖、不删除。提交后回读不确定时保留新引用文件，后续可直接读取回执。
- 外部上传登记的队列、异步准备与后台确认共用原调用的工程／运行／取消边界。只按回执的精确资产 ID 操作；重放先核旧目标和当前 claim，命令实际生效后才确认。已提交但回包丢失时以同 claim 的终态确认恢复，不重传文件。后台确认不重放用户后来删除的资产。旧 relink 日志缺少原目标证据且当前目标不符时保留日志，不能猜测覆盖；已匹配的旧日志仍可确认。目标比较不包含收藏、目录或转录等未被此次登记覆盖的字段。
- 确认队列的所有者失效后，新调用可以接管；旧回调及其 finally 不能清掉新所有者。取消清理以实际是否开始命令为界：确定未编辑时，同 claim abort 确认后才删除私有日志；已编辑或上下文已变时保留证据，不能拿新工程判断旧写入是否发生。
- 视觉对照的原子发布结束私有清理权限：取消只清自己的工作目录，不删除共享 HTML/索引。不同文件路径可有同一内容身份，不能靠进程内去重假设没有其他读取者。缺索引的 HTML 不是有效缓存，按原哈希校验在本地重建，不重调模型。
- 局部预览准备先写本次私有临时目录，再不可覆盖地发布。相同名称不代表相同字节；并发晚到进程不能截断已发布文件。导出遇到既有文件同样比较真实字节。
- 导出结果的目标重选只更新目的地，不重写已渲染结果的时间线、帧率等身份；已提交状态不能被旧重选、注册或错误回退。本地阶段与租约在同一 IndexedDB 事务内校验并写入，与服务端共用转换判断。远端回执只可合并匹配目标的当前本地句柄；缓存读取失败不能退用旧句柄授权。
- 源材料工具按作用区分当前性：会写稿件/分析的操作核对完整快照，ASR只读核对原片事实，历史观察可读但失配标stale。subject与packet及历史绑定必须由同一冻结输入派生；A→B→A的最终相等不能证明中途没有混包。进度回调后、付费派发前再核对运行/信号；硬截止后的非协作返回不能生效。
- 复核回执与审片板图片的消费同时绑定项目、运行、取消信号和完整规范化工程快照。请求前已取消不提交；JSON 或异步回执哈希完成后上下文已变，不暴露旧 pass 或图片。内容等值的新对象可读；短 revision 仅作原 HTTP 版本绑定，不能替代完整快照等值。原服务端回执保留，不因此重新调用。
- 人审页面按实际看过的板提交：主工程、兄弟片尾、任务与要求一起确定 identity。该 identity 是 HTTP 版本绑定，不能替代内容审核。取消、页面代次或上下文变化后，晚到响应不可写入当前工程或替换当前板。

## 成本与范围

仅存储竞争最多重读/合并三次，不增加外部重试、预算、模型选路、源窗或审批。raw 回读不抽帧、不重新提交。产物权威回读在异常路径发生；正常路径保留原写入。临时编码每次一份，发布后回收本次临时文件；比较既有产物会额外读字节。人审版本变化保留独立 HTML 快照，尚不宣称历史目录有全局容量上限。页面轮询增加兄弟工程身份读取，未据本地夹具时长宣称生产性能提升。

本机执行所有权/串行化不等于多实例分布式锁。休眠原型、演示与只读 UI 小状态保留，不为其新增制作状态或框架。当前工程、历史原判、失败计数和人工接受状态不属于修复对象。

### 已确认的代码路径

- SM17/68 的终审核对视频哈希。随后 `production-panel.ts` 的视频读取和下载检查渲染 ID、路径及尺寸。文件被同尺寸的其他字节替换后，下载缺少与终审哈希的比对。使用同尺寸替换和 HTTP Range 做回归，保留正常播放和下载性能。
- SM80/83 的浏览器动作仅在 409 恢复分支检查当前审片板。一般响应、后续状态读取和最终下载之间缺少同样的动作身份检查。在原动作等待时切换渲染或卸载面板，延迟返回可清掉新反馈或尝试下载旧片。浏览器实测留给该批次。

### 批次验收方式

每批以当前基线上的具名故障和涉及的状态边界为范围。沿生产入口重现反例，修复后复跑反例及同入口的合法流程。发生重启、并发或确认丢失时，分别检查用户状态、实际存储和外部提交计数。回归用原有夹具和假服务；只让现有事实源决定是否成功、是否接续。已通过的相邻边界加入批次验收，代码按实际失败调整。

批次独立可合并，复查跨批交界后再结束整个计划。遇到新故障先登记入口、影响、证据和所属批次；只有会使已排批次失效的前置依赖才调整顺序。生产进度、原判、额度和可回读产物在恢复测试前后逐项核对。验证输出使用本轮私有临时目录，进程退出后回收，只留小体积复现证据。

### SM94/96 · 同一工作目录的跨进程编辑与强杀恢复

**范围**　同一台机器、同一工作目录、两个独立 Node 进程，分别以 JSON 和 SQLite 为权威。入口为离线编辑 MCP 对应的领取、保存草稿、提交、丢弃，浏览器工程保存，及工程存储回读。正常竞争使用相同后端，另检查强杀后从 JSON 迁移到 SQLite。强杀点覆盖工程行、草稿行、离线提交最后一行、JSON 恢复途中，以及存储提交完成但尚无应用回执。网络文件系统、多机共享、数据目录搬迁、同时运行不同代码版本或强制不同数据库配置、断电与磁盘损坏另行验证。

**判断义务**

| 编号 | 事件 | 判断者与依据 | 预期 |
| --- | --- | --- | --- |
| P1 | 两进程竞争同一工程或共享索引 | 工程存储，当前项目版本、租约、索引 | 离线租约只能有一个获胜者。不同工程的合法提交都保留各自结果和共享索引。 |
| P2 | 进程在多行变更进行中强杀 | 同一存储的提交边界及实际持久化行 | 草稿保存、离线提交、浏览器保存各自全部完成或全部恢复到之前。其他进程看不到半提交。 |
| P3 | 进程在提交落地后、回包前强杀 | 实际项目、历史、租约与草稿 | 重开识别已提交内容。撤销后不能恢复已消费草稿。 |
| P4 | 回滚过程中再中断或持久化证据不可读 | 同一存储的恢复记录 | 恢复可重入。无法证明当前状态时拒绝当前操作，不能回退为无检查点。 |

**状态转换矩阵**

| 状态 | 其他进程读取 | 其他进程争抢或保存 | 现有写入者强杀后 | 用户撤销 |
| --- | --- | --- | --- | --- |
| 未进入变更，原草稿有效 | 可回读原状态 | 按当前租约裁决 | 保留原状态 | 按合法浏览器租约执行 |

| 恢复证据暂不可读 | 明确拒绝 | 明确拒绝 | 证据修复后按原路径恢复 | 明确拒绝 |

**序列与交错**

| 编号 | 实际入口与事件序列 | 必查证据 |
| --- | --- | --- |
| P-T1 | 进程 A 领取离线租约且尚未落盘，进程 B 并发领取 A 的工程 | 一个成功，一个忙，最终租约和获胜者一致 |
| P-T2 | 两个不同工程同时提交，或浏览器与离线编辑在同一工程争抢 | 持久化工程索引保留双方变化。提交后发生 JSON 日志清理异常或 SQLite 全文索引异常时，已提交结果保持有效。 |
| P-T3 | 已有草稿 → 离线提交在工程写入后或最后一条草稿记录删除后强杀 → 独立进程回读并恢复 → 同一草稿提交 | 从同一把锁内回读工程、索引、自动版本、租约和草稿。未提交时保留所有原记录。 |
| P-T4 | 草稿更新或浏览器保存，在工程或草稿行写入后强杀 → 重开 | 相邻的租约行和内容一起恢复，活跃写入时他方只看到一致状态 |
| P-T5 | 存储提交完成、未写应用完成回执 → 强杀 → 回读 B → 租约到期后浏览器撤销至 A → 离线重开 | B 已完整持久化，确认没有应用完成回执。A 回来时旧草稿仍已消费。 |

| 编号 | 任意序列完成后必须成立 | 核对依据 |
| --- | --- | --- |
| P-I1 | 同一时刻只有经当前租约授权的离线编辑能够提交 | 两个进程的操作回包与最终租约 |
| P-I2 | 存储回读只能观察完整旧状态或完整新状态 | 实际工程、草稿、版本、索引和租约 |

### SM94/96 · 数据目录搬迁与项目存储的一致性

**范围**　同机同用户的设置入口及其目录搬迁函数。核对有回滚记录的离线和浏览器编辑，当前 JSON 批量写入，以及工程、版本、索引、草稿、租约、删除记录和生成账本。设置指针的写入限制针对普通应用进程，显式固定到旧目录的维护进程仍按固定路径工作。SQLite 搬迁保持拒绝，覆盖请求前和等待锁期间取得 SQLite 权威。升级前已经中断且索引仍一致的历史批量操作缺少判断依据。整机断电、手工复制、跨主机和旧进程的写入另行验证。

**判断义务**

| 编号 | 事件 | 判断依据 | 必须兑现 |
| --- | --- | --- | --- |
| R1 | 源有未完成提交或正在写入 | 持有项目存储的进程锁，回读有效回滚记录 | 等待已开始的写入完成，或在崩溃后先恢复旧状态再复制。无效记录应拒绝搬迁。 |

| 编号 | 序列 | 验收证据 |

| R-I1 | 目标工程组来自一个可判定的提交点 | 独立进程一致读回工程、版本、草稿、索引、租约和删除记录 |

| R-I3 | 切换只发生在目标准备完成后，已在旧目录失去写权的进程不能成功落盘 | 实际设置入口和重开后的项目存储回读 |
| R-I4 | 外部模型、网关及导出调用为零 | 本地临时数据目录和子进程 |

实际入口回归为 `offline-edit-process.verify.ts` 的搬迁序列和 `data-dir.verify.ts`。单次测试使用新的临时目录，检查源和目标在进程重开后的存储与实际素材；源的编辑租约在复制切点有效时按原期限保留。

### SM94/96 · SQLite 数据目录搬迁

**范围**　同机同用户，普通应用的设置入口与同一版本的存储进程。核对 SQLite 主库中工程、工程索引、草稿、版本、任务、删除记录与已有搜索表，以及设置指针与代表性素材的回读。沿用上一批目标占用、JSON 搬迁和路径检查。显式固定数据目录的维护进程、手工写旧数据库、跨主机、文件系统断电另行验证。

**判断义务**

| --- | --- | --- |
| Q-I1 | 目标是同一个已提交 SQLite 快照 | 数据库完整性检查和独立进程对照实际数据。 |

| Q-I3 | 失败与重复请求保护已存在的数据 | 目标拒绝记录、原文件与再次打开的结果。 |
| Q-I4 | 外部生成、模型、网关及导出调用为零 | 本地子进程、SQLite、Settings 回环请求和合成数据。 |

实际入口回归为 `offline-edit-process.verify.ts relocate-sqlite`。在备份有进度且尚未完成时对真实子进程发出 SIGKILL。物理快照在切换前独立校验，Unix 上限制为 `0600`。计划内的写锁和备份耗时随数据量变化，当前证据来自隔离小库。

### SM59/60/61 · 同一数据目录的多进程任务与成片回读

**范围**　同机、同版本的 JSON 和 SQLite 进程。覆盖任务登记、启动恢复、状态查询、清理、成片转存和设置搬迁。测试使用临时数据目录和本地 HTTP，请求渲染时使用合成任务。跨主机、混合版本、断电、主动跨进程取消及应用之外直接修改媒体文件不在本批。操作系统无法确认 PID 已退出时保留原执行权。

**判断义务**

| 当…… | 依据 | 必须兑现 |
| --- | --- | --- |
| 同 ID 竞发，或先读后写不同 ID | 目录锁内读回的账本 | 只有一个登记持有者，保留其他 ID、首次输入和派发记录。 |
| 活任务遇到另一进程重开 | 保存的执行者身份和原接单证据 | 活任务保留原执行者。执行者死亡后，只有赢得恢复登记者可用原任务接续。无接单证据不重新发起。 |
| 成片完成但账本落盘失败 | 持久账本中最后一个已确认阶段 | 继续识别同 ID，终态取得持久确认前不公布成功，不重新渲染。 |
| 成片缺失或尺寸不符时请求转存 | 正式回执和实际文件 | 状态不提供可下载成片，转存也拒绝。恢复原文件后可按同 ID 转存。 |
| 暂存复制中断或与另一目标相遇 | 生成素材命名、相同目录锁、目标回读和实际字节 | 完整校验后发布。拒绝内容冲突并回收已过期的私有暂存。 |
| 设置搬迁遇到导出进行中或曾被强杀 | 持久任务状态、原导出尝试 ID | 进行中拒绝搬迁。结算后允许搬迁，已知失败尝试的媒体留在源目录。 |

**状态转换**

| 状态 | 同 ID 提交或状态查询 | 冷启动接续 | 清理或转存 |
| --- | --- | --- | --- |
| 尚未登记 | 登记一次，未写成功不得报已登记 | 无任务 | 无成片 |
| 活进程已登记 | 查当前同 ID，复用原输入 | 保留执行者 | 活任务保留，成片尚不可转存 |
| 执行者死亡 | 查同 ID 和已保存阶段 | 有接单证据原位接续一次，无证据记录结果未知 | 只按最新持久状态处理 |
| 终态待保存 | 保留最后已确认状态，可补存终态 | 按原持久阶段恢复 | 不使用待保存终态发布文件 |
| 终态已保存 | 读账本和实际文件 | 无重做 | 基于当前记录清理，原文件校验通过后转存 |
| 暂存尚未公开 | 继续使用原回执 | 同一 ID 可再次校验暂存 | 暂存超期可清理，冲突目标保留 |
| 搬迁遇到导出工作 | 活任务保留原目录 | 已终止的原任务先结算 | 搬迁仅跳过账本能确认的未成品 |

**序列与交错**

| 编号 | 实际序列 | 对照 |
| --- | --- | --- |
| J1 | A、B 同时暖启动 → 提交同 ID 或不同 ID → 第三个进程重开 | 同 ID 派发一次，不同 ID 都可读。 |
| J2 | A 已运行 → B 冷启动 → A 强杀 → B、C 同时接续 | 活着时不接管，退出后同一原任务只接续一次。 |
| J3 | A 持有旧缓存 → B 写入或清理 → A 查询和写另一个 ID | A 读到 B 的最新提交，后续写入不覆盖或复活旧行。 |
| J4 | 合成成片完成 → 账本写入失败 → 恢复账本 → 查询原 ID | 成片只执行一次，持久成功后才发布。 |
| J5 | 回执成功 → 文件截断或缺失 → 查询、转存 → 放回原文件 | 两个入口均拒绝坏文件，恢复后转存同一成片。 |
| J6 | 不能硬链接 → 复制中强杀、产生同尺寸错字节或竞争目标 → 转存 | 公共路径没有出现半份文件。冲突字节保留。正常复制通过，过期私有暂存可清理。 |
| J7 | 活导出写入部分媒体 → 设置搬迁失败 → 强杀并结算 → 再从设置搬迁 | 固定 JSON 账本和 SQLite 均受保护。已确认成片可搬迁，已知失败尝试保留在源。 |
| J8 | 接单字段写入失败 → 原进度接口查询。另测无关任务启动恢复遇到磁盘故障 | 接单字段未写成功时不展示。磁盘恢复后原终态可读，无关恢复没有重派。 |

**不变量**

- 同一 ID 的一次登记只取得一次派发权。已接单的接续按原任务标识回读。
- 持久写入只改预期的原行，其他 ID 原样保留。
- 终态及媒体对外可见前，各自的持久证据和实际文件必须有效。
- 不调用模型、供应商和实际渲染器。

`generation-job-process.verify.ts` 使用真实独立进程、HTTP 路由和 SIGKILL。`generation-job-state.verify.ts`、`export-receipt.verify.ts`、`export-runtime.verify.ts` 和 `upload-routes.verify.ts` 分别回归持久故障、旧回执、实际文件和写入命名。历史遗留且无账本可识别的文件继续按普通迁移规则处理。

### SM59/60/61 · 跨进程取消与导出完成

**范围**　同机同版本、共享 JSON 或 SQLite 的异步导出。使用实际取消、状态、清理入口和本地合成工作进程。进程死亡用 SIGKILL，文件和账本均在隔离目录。主动终止操作系统中的孤儿子进程、跨主机和混合版本部署不在本批。

**判断义务**

| 事件 | 判定依据 | 必须兑现 |
| --- | --- | --- |
| 多窗口或进程请求停止 | 账本内原导出行及同一次尝试 | 仅登记一次取消，正在执行的进程读取标记并停止。 |
| 取消撞上完成 | 同一账本锁内先提交的决定 | 成功先提交则保留结果。取消先提交则迟来的成功不得发布。 |
| 取消后任一进程死亡 | 已持久取消请求和原所有者状态 | 接受方死亡不丢请求。执行者死亡后按原 ID 结算，禁止派发。 |
| 重复取消、取消与清理交错 | 该操作的当前记录与 HTTP 意图 | 重复请求按现有状态回应。显式清理只能清理已经结算的记录。 |

**状态转换**

| 状态 | 停止请求 | 完成或重开 | 重复操作 |
| --- | --- | --- | --- |
| 无记录或不属于导出 | 拒绝 | 无该导出的可恢复状态 | 无写入 |
| 运行或排队 | 持久登记，返回待结算 | 原执行者仍负责停止 | 返回同一待结算状态 |
| 取消已登记 | 保留请求 | 执行者退出后结算取消，迟到成功丢弃 | 保留原登记，不触发清理 |
| 已成功 | 拒绝取消、保留文件 | 可回读并交付 | 独立清理仍由明确入口处理 |
| 已取消 | 确认原取消 | 不复跑 | 重复确认，不删除取消回执 |

**序列与交错**

| 编号 | 实际序列 | 对照 |
| --- | --- | --- |
| C1 | A 运行 → B、C 同时取消 → A 读取标记 | 一次工作、一次取消登记，原 ID 最终已取消。 |
| C2 | A 成功持久化 → B 连续取消。反向测 B 先登记，A 随后返回候选成品 | 第一种成片保留。第二种无成功回执和可转存成片。 |
| C3 | B 发出取消后强杀，或取消持久后强杀 A → C 重开 | 从原记录结束，不发生新增派发。无取消记录的崩溃仍显示结果未知。 |
| C4 | 账本取消写入失败 → 查询 → 恢复 → 同 ID 再请求 | 失败时无停止确认，恢复后按一次取消处理。 |
| C5 | 已取消重复、已完成重复、无记录与非导出 | 状态可区分，记录和其他成品保持原状。 |
| C6 | 已完成候选产物未能写终态 → 另一进程登记取消 → 原进程后台接续 | 不依赖请求恰好回到原进程。补存取消，清除该尝试候选，不再执行渲染。 |
| C7 | SQLite 主文件暂不可读、旧 JSON 仍有同 ID | 取消及状态返回 503。旧 JSON 保留，SQLite 恢复后读取原任务。 |
| C8 | 浏览器提交回包延迟 → 用户停止 → 收到原尝试标识。另测默认下载恢复只存服务端 | 只对原尝试发送停止。202、409、503 均保留恢复记录。重新打开能读回服务端绑定。 |
| C9 | 文件已改名至公开目录 → SQLite 拒绝终态写入 → 执行者强杀 | 取消请求和带有已保存取消的状态回读分别完成原尝试的结算与回收。已完成的其他尝试仍能回读。 |

**不变量**

- 停止请求和终态共享持久提交边界。
- 取消不会删除先已提交的成功结果。
- 只对原 ID 及原尝试生效，重复取消不会派发工作。
- 全部专项回归零模型、供应商和真实渲染调用。

使用 `generation-job-process.verify.ts` 的独立进程和真实 HTTP，再由 `export-receipt.verify.ts`、`serverExportOperation.verify.ts`、`serverExportRecovery.verify.ts` 补查实际排队入口与浏览器恢复。强杀后未公开的渲染、变帧率暂存由过期清理回收。取消已结算的 204 确认的是账本。对于已改名但终态未写成的候选文件，HTTP 结算后按已取消的尝试 ID 回收公开路径，过期清理也可接续。

### SM59/60/61 · 导出进程强杀与产物交付

**范围**　同机同一素材目录配置下的服务端导出。入口为异步任务状态、提升为工程素材、媒体读取和下载转存、素材目录切换，以及原生编码、变帧率和中间文件清理。使用独立进程、真实 SIGKILL 和本地生成素材，外部请求为零。Windows 的原生整树强杀、Electron 安装包、已运行的不同素材目录配置和系统临时目录的全盘清理未实测。

**判断义务**

| 事件 | 依据 | 必须兑现 |
| --- | --- | --- |
| 原生进程正在写时，执行者死亡 | 执行者持有的进程连接关闭，原生进程仍属于该次执行 | 停止该次写入，禁止同 ID 自动重派，其他活任务继续。 |
| 磁盘有候选文件，成功写入尚未确认 | 当前权威账本、原尝试 ID、结果路径与长度 | 状态、提升、普通媒体入口和转存均拒绝交付。 |
| 重开时已有成功回执 | 同一条成功记录与实际文件匹配 | 可读回及交付原文件。文件缺失或不匹配时保持不可读。 |
| 扫描遗留暂存文件 | 该尝试的所有者及文件年龄 | 过期后只清理已退出尝试的暂存，保留活任务和已提升的成片。 |
| 下载和清理同时发生 | 成功回执及真实媒体读取结果 | 可以读到已打开的文件，或仅终止该次连接。其他请求仍可正常处理。 |

**状态转换**

| 状态 | 执行者退出 | 重开、查找和交付 | 过期清理 |
| --- | --- | --- | --- |
| 在写暂存、尚无成功 | 停止原生写入，保留原任务记录 | 无成片可交付、无自动重派 | 回收该尝试的暂存 |
| 已改名、成功尚未提交 | 成为未确认候选 | 仍拒绝交付，不能凭文件推断成功 | 回收候选 |
| 成功已提交且文件完整 | 原成功保持 | 原文件可交付 | 按现有交付保留规则处理 |
| 成功已提交但文件缺失或不完整 | 保留回执 | 拒绝交付，回执可供追查 | 按现有交付保留规则处理 |

**序列与交错**

| 编号 | 顺序 | 观察点 |
| --- | --- | --- |
| N1 | 原生编码已写入 → 强杀 → 同机还有另一写入 | 原文件不再增长，另一任务正常完成。另测正常完成和取消。 |
| N2 | 候选落盘 → 拒绝账本终态 → 强杀 → 读取与转存 | 检查状态、提升、媒体 GET/HEAD、素材表、回源、签名代理和文件转存。 |
| N3 | 成功提交 → 强杀重开 → 读取原文件 → 截短文件再读 | 正例字节一致，反例无可交付文件。 |
| N4 | 原生中间文件残留 → 扫描 → 再打开 | 清理仅限过期失败尝试，已提升资产及活任务不受影响。 |
| N5 | 成功回执后清理与 Range 下载交错 | 受影响的读取失败可隔离，下一段读取仍返回正确字节。 |
| N6 | 运行中尝试切目录 → 结束后搬迁 | 在途时拒绝切换。只复制匹配成功回执的尝试文件，其他素材照常处理。 |

**不变量**

- 原生写入的归属随执行生命周期结束，同一 ID 不会由检查和恢复入口重新派发。
- 公开尝试 URL 必须对应同一条成功账本记录及一致的本地文件。
- 文件是否存在不能决定任务是否成功。公开的工程素材只能由已确认的结果产生。
- 本批只用隔离目录，所有回归零模型和供应商调用。

验证入口为 `export-native-recovery.verify.ts`、`generation-job-process.verify.ts`、`export-runtime.verify.ts` 和 `export-receipt.verify.ts`。原生检查可用 `CLIPMENTOR_TEST_EXISTING_CHROMIUM` 指向已经安装的二进制，追加真实导出和冷启动测试。

### SM59/60/61 · Windows 原生进程树与冷启动交付

**范围**　同一个 Windows 配置目录、实际 Node 执行进程、原生中间进程及持续写文件的 FFmpeg。分别强杀执行者、渲染工作进程和 Job 守护进程，通过本地 HTTP 读取重启状态及媒体。零模型、供应商或远程媒体调用。Windows Chromium、安装版 Electron、受限 PowerShell、NTFS 共享锁故障和跨主机存储均未实测。

**判断义务**

| 事件 | 判定方和依据 | 允许结果 |
| --- | --- | --- |
| 原生写入即将开始 | 执行者收到操作系统确认进程已纳入本次导出的 Job Object | 确认后开始。建组或加入失败则禁止启动原生写入。 |
| 执行者、工作进程或 Job 守护进程被单独强杀 | 进程连接、工作进程句柄或 Job 句柄，加上实际写入者状态 | 关闭本次进程组，保留此前已完成的其他导出。 |
| 冷启动遇到磁盘文件 | 持久成功回执和绑定的文件 | 有回执且文件匹配才交付，同 ID 回读不得重启渲染。 |

**状态转换**

| 状态 | 执行者退出 | 工作进程或 Job 守护进程退出 | 重开后交付 |
| --- | --- | --- | --- |
| 等待进程组确认 | 停止等待，没有原生工作 | 拒绝当前执行 | 没有成片 |
| 正在写文件 | 停止组内写入 | 组内后代停止，不发布候选 | 失败或结果未知，无文件可交付 |
| 文件已在公开路径、成功未落盘 | 保留原任务记录 | 不认领磁盘残留为成功 | 状态、提升和普通媒体拒绝交付 |
| 成功回执已落盘 | 保留成功结果 | 成功状态仍有效 | 原文件字节匹配，可交付 |

**序列与交错**

| 编号 | 顺序 | 验收依据 |
| --- | --- | --- |
| W1 | 写入实际 MP4 → 只强杀执行者 | 原生写入者退出，文件不再增长。 |
| W2 | 写入实际 MP4 → 只强杀渲染工作进程 | 原生后代退出，照常返回这个任务的失败。 |
| W3 | 正常导出提交成功 → 强杀另一尝试 | 已提交的另一产物完整，字节不变。 |
| W4 | 私有或公开位置留下未提交文件 → 冷启动 → 状态、提升、媒体和重复提交 | 成功文件可取得，中断候选不可交付，原尝试不重新启动。 |
| W5 | 已开始原生写入 → 只强杀持有 Job 句柄的守护进程 | 操作系统关闭唯一的句柄后，组内进程退出，任务失败且残留不可交付。 |
| W6 | 启动时取消或初始消息序列化失败 → 单独跑一次正常编码 | 失败请求无文件，正常直接 FFmpeg 有可探测的视频流。 |

**不变量**

- 进程归属须在原生写入前确定，进程父子关系快照不能作为回收证明。
- 查询和重启不会因磁盘出现文件而补记成功。
- 一次强杀只能影响该次执行，同配置目录下已有成功的导出保留。

**核验结果**

- W1、W2、W5 在 Windows 托管 runner 上分别强杀执行者、工作进程和持有 Job 句柄的守护进程。先观察实际 FFmpeg 输出增长，再核对进程树退出及文件大小停止变化。
- W3、W4 用成功文件作正例，冷启动后逐字节比对下载。夹具将实际中断字节放到公开候选位置，状态和媒体入口仍拒绝交付，提升返回 409，同 ID 提交仍绑定原尝试。
- W6 的早期取消及序列化失败没有产物，随后直接编码成功且 FFprobe 读到视频流。另以故障注入检查句柄身份不吻合及守护进程不确认关闭的处理。[PR Windows CI](https://github.com/bobwongagi-code/ClipMentor/actions/runs/44270344508)

### SM59/60/61 · 导出提交、断连接续和清理的组合验收

**范围**　单进程的异步导出 `POST /export/job`、同 ID 状态回读、显式取消，以及产品启动时的导出文件扫描。状态以 JSON 或 SQLite 任务账本及实际本地文件为依据。故障包括请求体未收完、提交回包丢失、重复提交、账本写失败、切换版本后撤销和过期清理。这里只检查导出快照的真实编辑历史撤销。操作系统进程终止、多实例并发、安装组件的产品流程与真实外部服务另行验证。

**判断义务**

| 当…… | 判定方与依据 | 允许结果 |
| --- | --- | --- |
| 请求断开或重发 | 路由先看请求是否已通过预检，存储再查同一操作 ID 的持久登记 | 未完成预检不排队。已交给任务登记的请求由原操作结算。重复请求等原存储提交，写失败时两方都不得回成功。 |
| 用户切换编辑版本再撤销 | 状态路由识别原 `renderId` 和已冻结的工程修订 | 原任务继续，另一个版本保留独立任务。返回旧版界面不产生新提交。 |
| 扫描找到过期文件 | 清理程序用任务里登记的文件 ID 找操作 ID，再查有效恢复状态 | 保留在跑或待交付的文件。可移除超期、无任务且无恢复记录的文件。 |
| 账本无法读写 | 每个按 ID 的 HTTP 入口以账本可读和写入确认作为依据 | 不能确认就返回 503；读到权威账本且其中没有该 ID 才能报 404。移除未完成时保留原记录和文件。 |

**状态与事件**

### 启动占位与正文确认丢失交叉（2026-11-17）

预览宿主写launch.claim后、尚未调用child run就取消，原来误记为已尝试一次并无法恢复。现只在本调用创建claim且能证明未进入run时释放；进入run后的异常仍unknown/消耗，不删除旧resumeChild占位。10项取消/配置/并发owner对照通过。

共享Storyboard在抽帧后、渲染前核共享来源，渲染后每caller独立核其实际文件。相同字节异路径的A损坏不会让健康B连带失败；来源在抽帧期间损坏仍阻断。

普通artifact与历史archive共用immutable body准备：正文写入报错后只在权威回读整record精确一致时继续；重启后同ID、同全部元数据、未索引orphan可完成原索引发布，已索引duplicate仍按原false返回，冲突body/metadata拒绝。未知确认保留现场，不以新ID覆盖旧记录。sidecar发布、quota、session和entry preconditions仍走原有原子边界。正文与索引确认丢失、重启、missingrun清理及归档同类入口均有永久正反例。copy实际proxy拒绝后本地attempt保守消耗、上游0的行为保持，非免费重发授权。
