# 分析与自审：问题驱动，不以动作清单代替解释

适用于新爆款的剪辑前分析及分析质量返修。先读 [pre-edit-analysis.md](pre-edit-analysis.md) 的证据和工具约束。本文件定义如何做内容判断，不新增模型、转写或审核确认权限。

先明确输入模式。协作制作要读取已有用户反馈，把影响卖点、画面解释及主次的反馈以 `operator_supplied` 保存并引用，注明来源和未独立核实项；不能只留在主审聊天里。明确的自主盲测才排除人工答案，另存测试工程与结果，不将事后补稿反记为自主成果。评价模型差距先对齐双方拿到的帧、转写和反馈：缺少输入与判断不足分开，不用主审独有的信息证明模型能力差。

## 1. 先理解购买关注，再确定观察任务

从源视频、已有转写与明确标来源的资料形成产品定位。分开记录：原片在宣称什么、画面可见什么、你对表达作用的解释。不要求证明商品真实功效或找出独家性能，才允许分析它的表达方式；常见拍法也可以贴合本品的购买理由。

速览覆盖开头、中间、结尾，按信息任务整理顺序与主次，不能只覆盖准备/使用而略过结果和购买邀请。镜头短不等于没价值，源时长长不等于值得长讲；不要先固定组数或把所有段落都变成核心亮点。

在速览之后，先列**少量会改变选点或解释的待解问题**，再补观察。问题写成可观察的区别，不写“再看看是否有亮点”。例如分清某段只是展示物件，还是通过物件、身体/使用环境、比较对象或反应传递了购买关注。不得假定其中一种解释已经成立。

每个问题只记四件事：源窗口；缺什么可见关系；要怎样补看；结果会影响哪个点。不要把内部推理写成长篇报告，也不要求为每个普通镜头制造疑问。

## 2. 按问题选图，短动作看短窗

`seconds` 适合全片定位与静态细节。若结论依赖靠近、转向、接触、指向、反应或阶段变化，就用 `sequence` 看疑问附近短窗口的起势、关键姿态和收势；把数十秒均分成八张图，不算核过一个短动作。

当某帧显示手/物体接近人或部位、主体离开比较位置、构图或覆盖状态变化，而用途还不明时，优先回看相邻短窗。若短窗仍没捕捉到关系，写清未解决的具体问题，不把“没看清”变成“这段只有普通动作”。对明显静态关系无需强制连续采样。

一次观察只解决一项或彼此相邻的问题，`reason` 写明它可能改变的判断。新视频先保留速览预算，再将剩余额度给重要疑问和自审修正；任务有次数上限时，在范围内安排，不绕过。达到预算即停，如实保留缺口。

## 3. 每组落成一条完整但简洁的关系

沿用现有字段保存，不另造平行分析包：

- `buying_reason_or_function`：买家在意什么，以及原作者如何回应；不能只填产品名称加“有使用/有比较”。
- `WHY` 解释证据：用具体画面说明“什么表达手段，让哪层信息更容易被理解或比较”，引用实际可见证据。动作可能共同完成一个任务，不按动作数量立卖点。
- `filming_conditions`：若删掉就无法借鉴的对象、位置、阶段、距离、同框关系或动作承接。不要罗列所有摄影参数。
- `intent_zh` 与 `line_guidance`：本组让观看者明白的内容，以及原片和解释如何组织、哪里重点、哪里简带。解释正文用平视分享口吻，内部证据和限制分开。
- `uncertainties`：每项写“未知内容；限制哪条断言；是否阻塞当前表达分析”。未知的真实功效、准确香型、价格或路径，不自动抹掉已可见的体验表达与段落作用；也不借表达分析补造它们。

“适合本品”不等于“只适合本品”。审核的是买家关注、当前画面与解释能否连起来，而非逼你为常规展示编一个独家优势。普通商品收尾要认清促单任务，但可以一句短带，不用为了缺少精确价格就改成只有产品辨认。

篇幅按信息价值分配。多次整理、拿取和包装再展示若只完成同一普通收尾功能，精选必要画面短带，不因动作多或源段长就全部保留、列为次重点。先弄清相邻讲话是否补充核心比较或条件，再决定删减；分析分组边界不是剪辑切点。

选定重点后，按 [planning.md](planning.md) 的“Selected-point baseline and explanation units”保存一份带稳定ID的重点清单及讲解单元，后续缩短、去重、锁稿均回查同一基线。不得以最新短稿倒推原本只有这些重点。保留、合并、删除及理由要可追溯；合并写清新落点，删除按主审权限处理。已经可见的体验表达不因真实香型/效果未知而消失，相关解释仍须限制在证据支持的范围。

清单由作者Agent首轮自己建立，不默认依赖主Codex替写或用户先确认。独立复核Agent不看作者理由，以原始重点、实际证据和最新声画对照做L1/L2；其结论不反记为作者自主发现或人工批准。脚本负责ID/落点/删除记录与变更失效，Agent负责判断解释价值及承接；字段齐全和自审通过都不能代替后者。独立调用须在任务授权预算内。

## 4. 起草后做一次逐组反证审核

按 [delivery-checklist.md](delivery-checklist.md) 留一份精简记录。不要三组复制同一个“已核对、没问题”。每组用实际内容回答下列问题；无问题项可合并记录，问题项才展开：

1. **价值有没有讲到？** 只读解释，能否知道观众在关心什么，为什么要这样展示？若只知道手/物体做了什么，退回补解释，而非换个术语。
2. **证据是否区分了相邻含义？** 比如展示物件、体验、结果比较、购买邀请承担不同任务；有画面ID不能证明你已选对功能。只在差异会影响结论时补短窗或回查原话。
3. **是否让限制取代主题？** 把内部未知暂时拿开，正文是否仍讲得清卖点和拍法？若只剩“不能证明”，重新区分表达意图与真实性验证，不虚构解决未知。
4. **是否丢了可借鉴条件？** 精简后是否仍保留必要阶段、对象与镜头关系？它们可以由画面或短标承担，但要说清在哪里。
5. **覆盖与权重是否合理？** 对照重点清单逐项核保留、合并或批准删除的落点，不能只检查最新版提纲内部自洽。原声出现不等于解释完成，回放范围改变须复核解释范围。重点按信息价值体现，不把所有镜头讲一遍；变更原定权重须记录依据，不凭旧标签锁死也不静默降权。

内部限制必须同步约束对外提纲。单帧未核清的体验、未锁定的表情窗口、身份或条件未知的比较，不得在前台改写成已发生的确定效果；先删去或只说已支持的拍法，如“同框方便对比”。若原话可能包含否定或限定，只将相关解释列为待核，保留讲话窗口，不扩大为全片停工。

发现问题时，只做一次有预算的局部补看/修订，再核受影响组及承接。结论用“可交内容审核／需修改／待核实”，写明范围。这里是模型内容自审，不调用 `review_clipmentor_analysis` 自行确认，亦非最终声音/画面验收。

## 5. 保存与效率

先完成观察和关系组织，再一次 `append` 保存收敛的证据、解释、点和蓝图。已有草稿只按稳定ID修订，不堆重复方案。每次成功工具结果已给出最新 `revision`，据此顺序写入即可；出现冲突、结果缺失或并发改动才先重读，最后统一复读验证实际保存。不在每个成功写入后重复读取整份转写和证据。

最终给用户一份可读蓝图，另附精简的待解问题处理结果及逐组自审结论。保留首稿与修订差异，不把人工答案或历史样片方法说成模型自主发现。无需把每个内部字段念给创作者，不宣称自审通过证明不会遗漏亮点。
