# Reproduce approved work

Use this branch when the user has approved a finished video and asks to reproduce its result, migrate it into editable layers, or export it through the built-in agent. This is a fidelity task. A new product or an explicit redesign still uses the planning workflow; do not turn this case's layout into a universal template.

## Establish the reference before editing

Identify each approved output, creator stage, corresponding native project/sequence and available source assets. Separate the approved video from later experiments. Record what was actually inspected. If only a rendered reference exists, inspect its compositions and transitions and recover their timings and layer properties before rebuilding; a transcript or coarse content blueprint is not a visual specification.

When a suitable layered project exists, prefer the supported project/sequence duplication tools, preserving the source project. Keep source footage, audio, captions, annotation code/props, transforms, keyframes, track order and transitions. Copying an editable sequence is valid reuse; importing the finished MP4 as one flattened replacement does not meet editable delivery. A migration project's existence alone does not prove fidelity to the approved video: inspect that correspondence too.

Record the reference video, candidate source project and destination sequence for each creator stage in the execution brief. Resolve references into accessible media and project IDs; a local path alone is not proof of access. If the approved output cannot be inspected, do not claim faithful reproduction or silently use the latest experiment as the reference. Complete safe preparation and identify the exact missing material. Do not introduce a "start from empty / choose a new geometry" constraint to test agent autonomy unless the user has requested that separate experiment; if requested, keep its outputs and acceptance separate from the approved deliverable.

## Preserve the actual design

For this reproduction, preserve the reference's media identity, source ranges, start/duration, speed, audio gain and fades, text, fonts, outlines, backgrounds, crop, position, scale, layer order, annotation targets and entrances, transition motion, and creator-specific ending. Read timeline instances rather than assuming pool templates are identical. Do not replace a title card with a subtitle, three meaningful panels with arbitrary strips, a backed label with plain text, or a side-by-side CTA with a vertical stack. Having the same words, subjects and total duration is not sufficient.

Use a copy for any necessary compatibility correction. Name the concrete unsupported property and the affected interval before changing it; do not silently substitute a font, compose a new layout, stretch timing or accept missing labels. Preserve everything outside the correction. If source data and reference disagree, report the mismatch and resolve it against the user's approved output instead of calling the copy exact.

Typography fidelity includes the actual font face and weight, measured glyph positions, line breaks, line spacing, outline width and label padding—not only the same words or font size. Browser auto-wrapping and combined stroke/shadow can change an approved layout. Recover explicit breaks and baselines from the reference; confirm the requested font is actually available rather than silently substituting it. When replacing MG instances, read back each start/duration/track after placement: collision avoidance can move newly added items even when the requested frame was explicit.

For audio, compare decoded reference and export with the same sample rate and channel layout. Mono-to-stereo conversion can explain amplitude ratios; do not blindly normalize them. If an approved mix cannot be reproduced from its historical source chain without changing timing or gain, preserve its actual mix as separately editable per-segment PCM clips, retaining the original sources and documenting this recovery. This is not a default for new productions, nor permission to flatten the whole video. Avoid double-playing embedded video sound plus the replacement audio. Verify the actual export and report any residual offset or encoding difference.

## Verify the reproduction

Use these checkpoints and record results with evidence, not an unchecked claim of compliance:

1. **Before execution:** the reference is accessible, each stage is mapped, allowed changes are explicit, and missing specifications are identified. With only a rendered reference, recover the relevant presentation before applying it; with a layered reference, reuse it rather than redesign it.
2. **Before expanding a rebuild or compatibility correction:** compare its representative rendered section, including the start, middle, end and transition. A lost title card, crop that hides the action, missing emphasis, or unapproved layout change stops propagation until corrected. An unchanged verified copy does not require another rebuild or redundant preview render.
3. **Before delivery:** read back actual timeline instances and compare the actual exports with the approved videos, including the common body and each distinct CTA. Record each significant deviation with its interval, viewer impact, disposition and evidence. Keep technical export success separate from fidelity and from listening/continuous-viewing status. Missing checks allow an explicitly limited preview, not an acceptance claim.

Immediately after duplication and before correction, read back the saved copy and compare all render-affecting fields with its source, allowing only intended identity/name changes and non-rendering selection state. Before a necessary correction, record its target items, fields, intervals and reason in the change list. After correction, allow only those recorded changes and verify everything outside them is preserved. Resolve any additional difference before delivery; do not add it retroactively to the list just to pass the check. Verify both creator-stage sequences separately and their common body. A successful duplicate or export proves execution, not fidelity.

Compare actual exports with the approved reference at corresponding output frames: invitation, explanation compositions, crop targets, captions, highlighted selling points, annotation entrances, transition windows and both CTA stages. Check that the important subject remains visible, burned-in and added text do not compete, and the reference's visual emphasis survives. Inspect transitions in motion; compare audio timing/gain and listen when the available tools support it. Record missing listening or continuous-viewing checks explicitly.

Distinguish exact timeline preservation, visual/audio fidelity, and byte/pixel identity. Re-encoding can change file bytes; unchanged audio assets do not prove the same rendered gain or timing. Do not invent a similarity threshold or describe partial frame checks as “100% identical”. Any missing approved element or unapproved layout change requires correction before fidelity acceptance, even when all selling points are present and export succeeds.

Judge remaining rendering differences by perceptible impact at the intended viewing size and playback speed. Prioritize meaning, readability, emphasis, continuity and intelligible sound. Do not spend further iterations matching antialiasing, tiny crop/line-width differences or sub-perceptual sample offsets after meaningful differences are resolved. Such differences do not justify redesigning an approved section. A perceptual-impact judgment requires appropriate inspection; frame samples or waveform similarity alone do not certify normal-speed viewing or listening.

Deliver the copied editable project and both requested outputs with the actual comparison result and unresolved differences. Use existing synchronous/asynchronous export contracts. Do not broaden this recovery into new-video autonomous analysis until the approved reproduction has been checked.
