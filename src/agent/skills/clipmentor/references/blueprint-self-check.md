# 蓝图作者自检

用于保存蓝图后、提交独立审核前的作者准备。分开执行零调用检查、作者自检和独立审核；前两层不生成批准，不取代既有门禁。本参考按需读取，不在每个制作阶段重复加载。

## 输入、轮数和记录

先运行本地只读命令 `npm run check:clipmentor-blueprint -- <候选.json> --md <查看稿.md>`。报告仅提示，不自动改稿或阻断保存／派发；估算不是声画验收，未命中也不是教学成立。报告读取现行候选与画面计划，片头片尾同样在检查范围内；有副本冲突先核现行对象，不把缺材料导致的空结果记成正常。

蓝图保存后，外部策划另开新会话自检，产品内策划使用新的运行。仅提供保存后的蓝图JSON、零调用报告及当前组原始证据／边界；不附写稿聊天、作者自评、旧审核或期望答案。JSON中已有的教学目标和安排仍是待核材料，不能照抄WHY、omission_loss来证明自己正确。不要为了自检添加或删除蓝图字段。本轮只提供指导，不自动创建运行或调用模型；新增真实运行沿用任务授权。

这是作者自检，即使用新上下文也不称独立审核。逐项引用原句／字段路径，写具体答案和`ok`／`fix`／`unresolved`；材料不足写未知，不能只写“通过”。自检和修改合计最多一轮，只修改受影响内容；按表达准则第7节记录修改项、必须保持项，修订候选记录上版hash。授权不含改稿时只列问题。

剩余问题记入现有`remaining_gaps`并标负责人和最晚解决阶段；自检过程记在现有交付记录的“作者自检”节，不另建批准层。作者自检记录、第一层诊断、预期标签与修改理由均不进入独立审核投影；独立审核仍只按现行材料及原有标准判断。

## S1–S7

| 编号 | 具体回答 | 需改或未知的情况 |
| --- | --- | --- |
| S1 | 每组引用实际文稿及画面，分别写买家关心／担心什么、她怎样表达、这样安排让哪个判断更容易作出以及依据；说明三者如何相连 | 只有动作清单；理由仅换词复述动作；从道具直接推导性能或观众心理。三栏是思考工具，不要求每句塞满公式，也不强制每个辅助点独立旁白 |
| S2 | 对“她说到…时就…”等每处原话或同步断言，列来源ID／范围，区分谁听过连续音画、只有ASR、只有图像；对照该组证据边界 | 把转写当直接听审；把示范当长期功效；忽略未知适用的对象。例：湿手指水滴不明与透明杯是否装水是不同问题，不能混为一个矛盾 |
| S3 | 逐句引用中马文，核对象、数量、条件、因果与承诺强弱 | 中文“带来销量”比马来文`dengan`更强；不能仅凭关键词相同判对齐 |
| S4 | 逐个达人结尾列行动与必要前提，核现有事实是否支持 | 已合作不等于已收货；不强制已合作版复述身份；消费者购买入口不能代替达人合作行动 |
| S5 | 引用视觉规格并指出作用元素、阶段、参考与有意变更 | 只说“蓝底白字”不指出是阶段条还是原片字幕；误把历史某色固定成所有视频的要求 |
| S6 | 逐条回应零调用报告的warn及INPUT版本冲突／未完成项：修改还是保留、依据是什么；修改须有授权 | 留空；为消除估算告警而赶读、削教学或凑时长；声长只参考组级实测与真实对象，不按单句秒差退稿 |
| S7 | 对照同段口播，引用画面文字、短标、产品卡是否另作数量、效果、收益或预算承诺 | 口播克制但画面扩张承诺。例：总广告预算有效不证明每人获得该额度；画面独有数字也不自动是错误，须核作用和条件 |

Green Makes v1是真实问题来源，不是未来视频的标准答案；具体材料见作者案例参考。本清单不送给独立审核当预期结论。

## 维护

后续真实漏检先归类：确定性事实进代码，具体可答的问题进本参考，教学取舍与节奏判断留独立审核／终审。新增问题须附真实来源，问题总数保持10条以内。重复词根启用前测误报；声长用同配置实测校准，报告误差，不写死语速。连续三支片无有效命中却有误报的规则列为待删，由用户决定，不自动删。

终审交付记录记“用户／审核发现且本应由前两层提前发现的问题数”，同时列具体问题和归类依据；未做终审记未测，不能写0。有效性看漏检是否下降，不能用加载通过或规则数量增长代替。
