# ClipMentor 每版交付检查记录模板

这是2026-10-13生产工作区模板的仓库便携版。复制到本次任务支持的记录位置后填写，不直接把本模板当成检查结果。参照[复现经验](reproduction-lessons.md)及[蓝图流程](planning.md)；必要时按[复现流程](approved-reproduction.md)执行。不要假设本机父目录文档在其他同事环境中可访问。各项填“通过／不通过／未检查／不适用”，通过必须有依据；不能默认勾选，不能以旧版记录覆盖改动后的实际状态。

> **技术通过不能替代内容验收。** 字幕同文只证明文本相同，不证明定稿正确；完整解码只证明文件可解码，不证明声画对应；抽帧只支持采样画面，不证明连续动作或观看顺畅。最终交付还须实际听审、正常速度连续观看和每个重点的声画核对；文字/代码任务如实记不适用，不假造通过。

### 待核实项的关闭责任

沿用本次同一份记录，每项填写下表；不要把表达建议混成关键未知。具体职责、升级和最终放行按[review boundaries](review-boundaries.md)执行。

| 单元/重点/句子ID | 缺什么证据或决定 | 负责人 | 允许的补证/处理方式 | 必须解决的阶段 | 阻断范围 | 关闭证据与复核结果 |
| --- | --- | --- | --- | --- | --- | --- |
| 待填 | | 作者/独立复核/提供业务事实的操作者 | | 配音前/剪辑前/交付前 | 当前整体回执/最终交付/非阻断建议 | 未关闭 |

最终记录明确：产物版本与位置、待审/正式状态、尚缺检查、负责人和下一步；只有适用内容/声画/技术验收及真实操作者接受均有依据，才从待审转正式。不能用plan-ready代替。局部修订先列变更和受影响项，复用未变依据；有两个明确工程快照时可用`diff:delivery-check -- before.json after.json`辅助，不把差异报告当验收。

## 0. 所有输出物的轻量总审（发送前）

覆盖分析与蓝图、拆解视频、Storyboard、文案、合作邀请及随附说明。内部候选可交审核，但标明待审，不冒充可发给创作者的定稿；面向创作者的产物按其实际使用方式审。

共用四项检查，不另建平行评分体系：

- **对谁、有什么用**：读者、用途及本次要传递的信息明确；拆解解释产品购买理由与具体拍法，Storyboard 忠实还原原片，合作邀请符合当前合作阶段，不相互串位。
- **怎么说**：平视分享，不贬低、不训话、不虚构赞美；用具体、自然且适合当地理解的表达，避免后台称谓堆砌、机翻长句、术语和俚语堆砌。不机械禁词，也不强制先夸。
- **说得是否准确**：卖点、必要拍法条件、数字与承诺有依据；中马意思一致，未知未写成事实；不承诺某动作必然多出单。亲切提示不改丢实质限制。
- **拿到能否使用**：信息和呈现适合当前产物，可看懂、可回看或可照拍；需要行动时有清楚且真实的下一步。不是每份产物都加 CTA，也不向客观 Storyboard 塞点评。

沿用本模板后续已有的专项检查和证据，不重复填写同一问题：文案看文案关卡，成片看实际声画和技术结果，Storyboard 看三列、忠实性及可照拍性；内部分析重点看证据与不确定项。审核备注留内部，对外只保留影响使用的必要说明，用日常语言表达。

| 输出物／版本／位置 | 读者与用途 | 共用检查及专项依据 | 问题／处理或未检查项 | 审核者与方式 | 结论 |
| --- | --- | --- | --- | --- | --- |
| 待填 | | | | 自审／主负责者复核／实际人工反馈，如实填写 | 待核实 |

结论使用“可按本次范围交付／需修改／待核实”，写清范围。存在影响准确性、理解或使用的错误，先修对应部分；关键证据或必要检查缺失，不能报通过。一般风格偏好记录取舍，不自动阻塞。检查能力不足时可交明确限定的待审稿／预览，不称最终通过；自审不称独立或人工审核。

效率边界：一批产物可共用一份记录；同一版本已有有效检查直接引用；局部改动只复核受影响内容与承接关系。普通状态回复发送前快速自查即可，不另生成表格；不默认增加模型、子 Agent、母语逐句听审或用户逐项批准。只有重要未知影响当前结论时才升级核实，不为小措辞反复整片返工。

本节与后续专项记录可以合并：已有文案／声画审核记录补齐读者、用途与交付结论即可，不为同一问题再填一张表。无问题的内容记覆盖范围和依据，逐条明细只列需要处理的错误、待核实项及有实质取舍的建议。

### 执行交接与范围检查

- 任务类型：新创作／局部修改／已认可作品复现。工具链试验如另有要求，单独标明，不替代成片效果目标。
- 效果基准及实际可访问位置：认可成片或已批准蓝图版本；迁移稿、试验稿不自动升为基准。
- 执行目标：工程、序列、达人阶段及其对应输出；双版本分别登记。
- 可改项／不变项／尚缺的执行信息：不能只交台词、卖点和总时长，让执行者自行重设计已认可布局。
- 主 Agent 发给执行者的任务是否保留上述约束：检查后填写。复现已有分层工程优先复制复用；不以证明 Agent 会搭建为由禁止复用。
- 正常制作沿用[分阶段交接](planning.md#production-stages-and-ownership)：分析时定位原片证据，蓝图确定讲什么、怎样表达及需要什么画面；蓝图确定后落实原片片段/关键帧和已提供素材，逐项关联单元/重点/用途并核对可访问的文件或asset ID，再补实际音频声长、意群画面及落地指令。策划负责取舍，执行者不再重新猜重点；外部找素材/建素材库另定范围，自主测试也不作为生产默认限制。使用本记录及现有工程计划，不重复造表。

默认由内置Agent起草蓝图和重点清单；主审提供用户反馈、业务口径、已确认决定并核查清单，不代写。仅在用户明确要求时采用外部提供的蓝图，标明来源，不反记为自主发现。这些信息由 Agent 从已有上下文整理，不要求用户重新填写或重复确认。基准不可访问时可继续安全准备，但不能凭记忆声称复现。

### 分阶段检查结果

| 关口 | 本次结果／证据 | 未通过时处理 |
| --- | --- | --- |
| 开工前 | 基准、范围、两版目标和素材可访问性 | 补缺失信息，不擅自换基准或设计 |
| 配音后、放置前 | 实测音频及相关气口与本单元画面任务已协调；逐意群的关键动作有落点；估算窗与实际秒数分开 | 交策划调整受影响的声画分工/文案或表现，复核变化；不让执行者用慢放、循环、空定格或赶读填差额。此项是工作流复核，非新增自动时长门禁 |
| 扩展前（新建或重建表现方式时） | 代表段实际呈现的构图、文字、标注及交接；每种不同 CTA 单独核对 | 缺关键元素或明显错配先修该段，不复制问题到整片；不变且已有有效检查的段落不用重复渲染 |
| 首次可审预览／内容变更后 | 执行者先自查实现；新起的独立复核Agent按下文隔离要求检查L1覆盖和L2承接，不读作者理由或自评；记录实际所见证据与范围 | 两项均通过才连同相关局部／技术检查交最终人审；失败或关键未知先退作者。未获调用授权或证据不足，只交限定待审预览；未变且有效的证据可复用 |
| 交付前 | 时间线实例回读＋实际输出对照；复制时核对一致，修正后按预先登记的变更清单核对；显著差异、时间点、处理结果；听审／连续观看分别登记 | 有明显未授权偏离不报效果达标；缺检查只交限定预览，不报完整验收 |

检查按观看效果决定优先级，不追求像素或采样级同一。关键卖点、信息层级、可读性、声音清楚和连贯性不能省略；不影响这些的细小字边／线宽差别不驱动新一轮重做。这是工作流要求，不是已经实现的程序自动导出拦截。

| 购买理由／核心卖点 | 原片位置及关键数字 | 本段必须讲清的关系 | 讲解口播 | 醒目文字／可见动作 | 成片时段 | 结果／证据 |
| --- | --- | --- | --- | --- | --- | --- |
| 待填 | | | | | | 未检查 |

区分原片说了、女声说了、画面写了。不能用“原片出现过”代替重点已经解释，也不能遗漏产品核心功能而只谈剪辑手法。

引用工程内 `source_breakdown` 的同一份重点基线和讲解单元，不复制另一份会漂移的清单。作者Agent首轮建表，不默认交人逐项预审。`read_clipmentor_analysis` 的 `breakdown_check` 核覆盖、处理理由、回看关系和文案源窗；`breakdown_timeline_check` 从真实实例推导实际源范围。独立审核包须从该基线构造，不接受审核时自行缩小任务。理由存在、范围吻合不等于价值已讲清，语义仍由独立审核负责。范围或文字变化使现有制作回执过期，还原也不自动恢复；当前是整份回执保守失效，复核可复用未变化依据。

### 内容到技术的复核顺序

有预览时，先正常速度完整看本次待审预览，再依次查L1/L2；仅有提纲时可查计划，但不得冒充成片通过。连续观看、实际听审及取样检查分别记录，能力不足或未做的项目明确标记。

| 层次 | 查什么 | 记录结果与证据 |
| --- | --- | --- |
| L1 重点覆盖 | 与已确认清单逐项对照，所有重点、必要条件有解释落点，合并/删除有依据；不是只在原声出现 | 未检查 |
| L2 组内及组间承接 | 讲解解释刚看到的内容；回看能看懂对象与理由，使用/比较阶段不混淆，前轮决定的前提仍成立 | 未检查 |
| L3 局部配图 | 具体口播、字幕、画面、短标与指向的含义和时机对应 | 未检查 |
| L4 技术检查 | 时长、速度、字幕可读性、音轨、导出完整性等；实际听审另记，不用解码成功代替 | 未检查 |

上一层有实质问题或关键项目未检查，先处理受影响单元，不继续以细节打磨或技术通过掩盖内容缺口；诊断所需技术探查不受此限制。未变化且已有有效证据的记录可复用，只重审变更及依赖，不默认重做全片或增加模型/同事审核。首次复核记录L1/L2是否直接通过，以及遗留内容问题与重点ID，不以新增规则已加载推断防复发成功。

首次可审预览的L1/L2由新起的独立复核Agent负责，不由剪辑执行者的自审替代。它只接收原片时间轴/证据访问、原始重点清单和当前讲解画面对照，不接收作者取舍理由或自评。L1查高价值重点是否让观众明白“为什么值得学”，L2查讲解是否承接刚展示的内容；否或关键证据不足先退作者，按授权轮次修订复核，不把每一轮都交用户。结构核对通过、L1/L2及相关局部/技术检查通过后，附一页重点清单、删除记录与复核结论交最终人审；有未听审/未观看等限制就明示，不能包装成已通过版本。

L2逐单元按成片顺序先看原声证据、记录实际可见内容，再看讲解证据，填写下表。通过须引用前后两端，不能只凭讲解内部“先A再B”成立或相同单元标签通过。回看不强制固定措辞，由真实语言、画面组织或上下文判断是否易懂；未提供的原声含义/发声边界/连续运动不补猜。可判断的视觉/文字关系与未知的连续视听关系分开给结论，证据不足影响对应项目，不用免责声明给整体pass兜底，也不因无音频一概否定已有视觉证据。

| 单元 | 前段原声实际展示及证据 | 后段讲解内容及证据 | 相同／新增／回看关系 | 实际承接线索 | 可判断范围与缺口 | L2结论 |
| --- | --- | --- | --- | --- | --- | --- |
| 待填 | | | | | | pass／needs_revision／insufficient_evidence |

每项目只新增两项人工成本结果：最终看片发现的内容问题数（另列措辞建议，不混计）和用户实际花费分钟数，未知不估造。每个内容问题标“首轮选点／修订丢失／表达错位／复核漏检”，允许多因，不据数量仍高就断言首轮分析有问题。连续3项目零内容问题可作为提议抽检的试行信号，不自动取消最终人审，须用户明确改政策；同时记录样本类别和检查方式的局限。

### 教学关系的证据与独立结论

将L2分开记录为**叙事关系是否可理解**和**教学关系是否传达**。前者通过不能代替后者通过，也不要求两者必须同判。回顾可以成立，但不能把“补齐过程”或主题相同直接升级为教学讲清；回看来源时间倒退本身也不是错误。

对每个重点及讲解单元引用成片中的实际落点：口播/短标给原句与预览时间；由画面组织承担时，说明具体对象、阶段与组合如何传达目标价值。目标清单里的解释不是成片原句，原声里出现动作不是已完成教学。完整意义可由同组多句与画面共同承担，不机械要求每句重复卖点、拍法和作用。

独立复核不接收作者取舍辩护、旧判或期望答案；允许明确的回顾通过，也允许某项教学不足而叙事通过。原始判断与代码校验结果分开保存：代码只验证引用、时间、覆盖和字段，不证明视觉解释或价值判断为真；引用齐全仍不能单独视为语义验收通过。单元绑定的重点存在漏讲或缺证据时，即使模型给叙事/教学总评通过，该单元仍需复核；保留其原始总评，不改写成模型已经认同错位。未核实的引语、缺失单元或无依据正判进入待复核。保留模型与用户观看的分歧，不追加调用直到获得指定答案。

产品内的服务端复核模块为`server/clipmentor/preview-review.ts`，CLI为`server/clipmentor/preview-review-cli.mts`；本地入口为`npm run review:clipmentor-preview -- --video <MP4> --input <JSON> --out <新结果JSON> --operation <UUID-v4>`，在应用仓库运行。服务端环境`ROOTIFY_GATEWAY_API_KEY`统一供给；本地开发可从Git忽略的`.env.local`读取，不把密钥交给浏览器或Agent文稿。

输入JSON包含`duration_seconds`、`points:[{point_id,teaching_goal_zh,product_relevance}]`、`units:[{unit_id,point_ids}]`和`reference_text:[{channel:"narration"|"annotation",start_seconds,end_seconds,text}]`。单元需包括本次要审的组间衔接；文字从真实工程提取，不能把作者希望表达的意思填作已存在的原句。输出同时保留模型原始公开JSON、单元的narrative/teaching判断、问题码、输入/视频/指令哈希及版本。`pass`仅为本次语义复核，不是完整成片放行。

该入口固定使用已验证的3.8公司网关内联线路，不上传外部URL，不压缩或切开视频，包含Base64及文字的请求超过100MB则在调用前拒绝。2026-10-19官方外部URL上限为每文件15MB，不能用R2上传/回读成功代替上游大小检查；未来更大文件需另行验证Files API等线路，不自动换Provider。600秒超时、失败计数、操作ID账本和无自动重试保持一致；同操作成功复用结果，失败/不确定不重发。接口成功、模型质量和最终音画验收分别记录。

### 文案复核（配音前；文字任务也适用）

依照[蓝图流程](planning.md#narration-necessity-and-transition-checks)的四问：**值得讲吗／讲得直接吗／说得自然吗／证据支持吗**，在下方原有记录中逐句结合整组给依据，不另建评分表。缺核心教学意思、必要条件或有事实越界为必须修；已清楚准确、仅可更顺口的是表达建议；影响当前结论的证据不足为待核实。不得互相抵消或只凭“略显生硬”判废。不以“改了几句”代替结论。只有文字时，实际声长、字幕可读性和最终画面承载保持未检查。

| 检查 | 本次结果／证据 | 未解决项 |
| --- | --- | --- |
| 视角与作用 | 观察、解释原达人；整组讲清具体做法怎样表达购买理由，不训话、不只报动作 | |

### 文案审核关卡与放行记录（必须填写）

先按[三个审核检查点](planning.md#production-review-checkpoints)记录：配音前蓝图整组L1/L2与逐句四问 → 实际声音后的声画承载 → 初剪后的连续视听。`group_checks`只审计划教学关系，不能代替成片承接；阶段未到的项目记未检查，不反过来阻止草稿保存。代码会拦住缺失、未通过或过期的计划回执，不证明语义判断正确，也未自动验收实际声画容量。

起草完成后先自查，不以“已按准则写稿”代替检查；自查只表示准备好送审，不是制作许可。内置Agent保存当前稿和各单元当前画面方案后，在明确的一次调用授权内使用`request_clipmentor_copy_review`：宿主从工程生成材料，复用本地Codex登录另起隔离上下文，只读源片采样，按同版结果写回独立回执。作者不能提交通过结论；失败或未知保留，禁止自动重试。没有授权时停在待审，不把自审冒充独立审核。此处是配音前文案／计划审核，后续实际预览L1/L2仍须按前文进行；不新增外部服务或默认每句母语听审。

- 被审版本／可定位的同版文案位置：
- 段落、句子和短标 ID／目标达人阶段：
- 起草者／审核者／审核方式／日期：
- 上表每项结论：通过／不通过／未检查／不适用；逐项写证据，不适用需理由。

审核记录保留原句和修改理由。没有发现问题也应给出覆盖范围及依据，不强行改句证明审稿工作量；单句合格不能代替整组卖点、拍法条件及承接关系已覆盖。

审核意见的引文须能匹配本单元实际口播、字幕或短标，不能引用中文释义、其他单元或背景资料代替原句。代码仅归一空白后匹配原文片段，不证明意见本身正确。`production_gate.code=copy_finding_evidence_invalid` 表示审核依据不足：保留原判及引文，先核对受审版本和引用位置，不据此要求作者改稿，不按旧pass制作，也不自动追加审核调用。回读已保存回执仍执行此检查。

| 结论 | 判定与下一步 |
| --- | --- |
| 文案通过 | 上表所有适用项已核对；没有未解决的必须修项或影响当前文案的关键未知；不适用项有理由。自查通过只可送独立审核，不能进入实际合成；当前整体独立回执有效且production_gate允许后，才可执行另获授权的配音或制作。不代表母语、声音或成片通过 |
| 需修改 | 有事实越界、核心遗漏、双语错义、字幕不同文，或明确影响理解的表达问题；退回对应句或组，修改后复核再放行 |
| 待核实 | 缺证据、关键语义无法判断、必要检查尚未做或规定的听审前置项未完成；修受影响内容、复用未变依据，但当前整体回执不通过时所有受控制作均阻塞，其他段落只可继续不受门禁限制的准备；不得把未知填成通过 |

一般风格偏好不自动阻塞，记录采用或保留理由；不能把明显生硬、意义含混一律降为“风格”。整组结论取未解决的阻塞项，不用平均分或总分抵消错误。

若整组只给内部概念或泛作用，创作者仍不知具体拍法怎样服务本品购买关注，判“需修改”，不能仅凭无越界、引用完整、字幕同文通过。按整组已传递的信息判断，不机械禁止某个词，不强制每句重复全套关系；复核仍使用上述同一记录，不新增默认调用或并行报告。

实际执行这项检查时，先只读面向创作者的同版口播、字幕/短标和画面计划，在现有记录中简短复述“能理解的具体拍法及其与本品的关系”，引用稿件原句或具体画面关系；再对照交接要求找缺口。不能从作者理由或内部依据补全稿件未表达的意思。中文意思也须忠实对应马来稿，不能靠中文润色替它过关。返修只退回未讲清的关系、丢失的必要条件或不自然的具体位置，不给替换句、不要求全稿重写；改后重查受影响部分。当前只能完成文字判断时，如实保留母语和实际声音项未检查。

- 本次文案结论／放行句子范围／未放行句子范围及原因：
- 表达建议的取舍／未完成的母语、声音及画面检查：
- 下次复核触发条件：文案、字幕、短标、所依证据、关键画面、合作条件或达人阶段变化。旧通过不自动沿用；只重审受影响项及承接关系，保留其余有效记录。

配音后再核实际发声和画面预算，剪辑后按第 3 节核最终实例及输出；这两道检查不能提前记通过。现有Agent公共入口有文案/计划制作门禁，提交导出还检查登记的实际源范围；没有自动完成母语、听审、连续视听或最终成片验收，也未接管手动UI导出按钮。结构通过不代替这些检查。
