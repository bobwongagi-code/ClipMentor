# Brief and blueprint

This is an agent working format, not a form the user must fill in and not an executable timeline schema. No new service is required. Translate an accepted blueprint into existing editor tools.

## Hard rules (read first)

These five rules take priority over revision convenience. The rest of this file explains their application.

1. **The selected-point baseline is the reference.** After every shortening, deduplication, translation or locking round, account for each selected point: retained, merged (with destination) or explicitly removed (with reason and required review). No point silently disappears.
2. **Changing original playback reopens its explanation unit.** A changed playback range makes the linked unit pending, even if its wording is unchanged. Re-check coverage and whether any revisit is understandable and justified; no fixed spoken rewind phrase is required.
3. **Map every required picture before editing.** Resolve it to usable assets/ranges with a clear purpose and the readability checks below. Missing essential material returns to planning; the executor does not pick unspecified footage.
4. **A timing shortfall changes allocation, not selection.** Reallocate words, picture and composition by value; timing alone never authorizes deleting a selected point. Already appearing in original playback does not remove the need to explain why a point is worth learning.
5. **Review top-down and stop downstream polishing at a failed layer.** L1 point coverage → L2 unit handoff → L3 local picture/line match → L4 technical checks. L3/L4 passes never imply L1/L2. Diagnostic checks may still proceed; missing evidence remains unresolved.

## Production stages and ownership

Normal production uses the following handoff. Reuse the current project's analysis, source_breakdown, current copy/picture plan and existing execution/review record; do not create another independent checklist or replay every stage for a local fix.

| Stage | Owner and required output | Ready for the next step when |
| --- | --- | --- |
| Product and complete-source understanding | Planner: product buying reasons, persuasive structure, original claims / visible actions / interpretations, material unknowns. Use Hook/S1–S6 or other relevant analytical structure to understand the actual video, not force it to contain every stage. Apply the bundled analysis-method and pre-edit-analysis references. | Selected points explain a product-relevant method and have inspectable source evidence; unsupported claims remain withheld. Sampling is not reported as continuous viewing. |
| Editing blueprint | Planner: selected units in source order, priorities, coherent original-playback ranges and evidence anchors, why each point is worth learning, narration/picture/short-label division, picture requirements, composition and original-to-explanation handoff. | The teaching argument and what each picture must convey are specified; original observations support those decisions. Final preparation/import of every production asset is not a prerequisite to drafting the blueprint. Guidance allows later timing adjustment; it does not fix estimated seconds as immutable slots. |
| Material preparation and mapping | Planner/material preparation: turn the settled blueprint's requirements into actual source clips/keyframes, supplied product images, sales screenshots, existing audio and other available inputs. Resolve file/asset IDs, source ranges, usage and material gaps before timeline editing. | Each required picture has an accessible candidate mapped to its unit/point/beat, stating what must be seen, its planned viewing time and readability-check result. Accessibility alone is not readiness. Mapping establishes usable source ranges, not final cut points; after real-audio measurement, adjust in/out within those verified ranges without repeating material preparation, provided the required action and meaning remain intact. Missing essential assets return to the planner; the executor is not asked to search for an unspecified suitable shot while editing. External search/library building is separate scope. |
| Localization and real-audio calibration | Planner/writer: natural observed-example narration, same-word captions and faithful Chinese meaning, reviewed against the blueprint before authorized synthesis. Reuse unchanged approved audio; measure each reused/new file and relevant pauses against the planned picture tasks. | The measured voice and an information-bearing picture arrangement are reconciled at meaningful phrase/beat boundaries. Text/plan approval alone does not establish timing. Requested listening or final-viewing checks retain their separate status. |
| Executable editor handoff | Planner: the actual versioned instructions described below; executor checks assets, source/output clocks and permissions before mutation. | The executor can implement without re-deciding the selling point, footage identity, narrative argument or composition. Missing material/timing is returned as a concrete conflict, not filled with arbitrary footage or holds. |
| Preview and local correction | Executor: editable project, authorized preview, saved-instance readback and implementation self-check. At the first reviewable preview, a fresh independent Agent context receives the source timeline, selected-point baseline and per-line explanation/picture mapping, with timestamped frames from both original playback and explanation; exclude author reasoning and self-evaluation. It checks L1 (is each high-value point's learning value communicated?) and L2 (does the explanation connect to what was just shown, including any revisit?). | L1/L2 pass before downstream L3/L4 polishing and, together with applicable local/technical checks, before final operator review. Failures return to the planner with affected unit/point IDs; the reviewer does not rewrite. Fix execution deviations in affected instances only. Reuse valid unchanged evidence; changes refresh affected review. Calls require authorization. Missing review or critical continuous-motion/audio evidence permits only a limited pending preview, not a passed delivery; frames alone do not certify continuous viewing or listening. |

**Default authorship:** the built-in product Agent drafts the analysis, selected-point baseline and blueprint from inspected evidence. The lead/reviewer supplies confirmed user feedback, business wording policy and prior approved decisions with their reasons and premises, then checks baseline accounting rather than writing the blueprint. A lead-written blueprint is used only when the user explicitly requests it; record it as externally supplied, not an Agent discovery.

When carrying a decision forward, pass its reason and premise, not just its conclusion. Avoiding redundant replay and explaining a point's learning value are separate decisions; a reason for the former does not settle the latter. If a premise no longer holds, reopen the affected decision. Keep these reasons in the authoring handoff, separate from the isolated review packet below.

Do not withhold necessary inputs to test autonomy; an isolated autonomy test requires an explicit user request and honest provenance. The same product Agent may plan and execute in separate stages; the executor implements settled decisions, reads back saved instances and returns concrete conflicts. Independent L1/L2 review remains a fresh-agent responsibility within the authorized budget, not executor self-review or replacement writing. No new provider, service or repository dependency is required.

### Map available material after the blueprint

Separate original-evidence discovery from production-material preparation. During analysis, locate enough real source evidence to justify the selected teaching point. After the blueprint is settled, organize the actual clips, keyframes and supplied inputs that will express it; do not demand that every final crop, frame cut and imported asset be locked before the teaching plan can be written.

Use the current plan/execution brief for a compact mapping: `unit_id / point_id / beat → picture requirement → source kind and accessible file/asset ID → source range/frame when applicable → intended use and current gap`. No new registry/schema or mandatory second checklist is needed. Verify access/import through supported tools; a listed path alone is not an available editor asset. Keep original footage, supplied marketing/cooperation imagery and performance screenshots identified by their actual role. Product imagery supports product recognition; sales screenshots retain their metric/period and do not prove the demonstrated product effect. Match assets to what the blueprint needs rather than forcing every supplied file into the video. Unless explicitly requested, use available original/supplied material without web/stock search or library construction.

For each candidate, record the usable source range separately from any tentative cut, plus the object, contact or detail viewers must recognize, the planned viewing time and whether that target was actually checked at the intended crop/output size. An untested duration is a planning budget, not proof of readability; merely locating a frame does not clear the affected picture requirement. Judge only the detail the teaching point needs, not unrelated fine texture. Check continuous action for an action relationship rather than treating one frame as proof. After audio calibration, recheck the affected picture if its crop, composition or viewing time changes; do not restart unchanged material preparation. A change beyond the verified range or to the teaching meaning returns the affected plan for review, rather than silently inheriting readiness or an old approval.

### Resolve timing at the unit level

The blueprint fixes selected meaning and required filming conditions, not one sentence = one source clip or estimated second count. Use a group's complete argument to decide what must be spoken, what a specific short label can carry and what the visible relationship already explains. Do not repeat every visible action in narration; synchronized captions still use the narration's exact words, not a second shortened script. A necessary condition assigned to a label/picture must actually be legible and visible at the relevant point, not merely listed in internal notes.

When measured voice does not fit, the planner revises the unit's narration/picture allocation and presentation: remove redundant wording while preserving selected meaning, use appropriate continuous source action, or use a meaningful comparison/composition/close-up/brief annotated hold. Use the actual material, not a mandatory grid or fixed order. Do not convert a seconds deficit into an equally long frozen frame, slow/loop footage, accelerate speech or cut words. Source duration, measured audio duration and planned still-frame reading time are different quantities; group totals alone do not prove phrase/action alignment. Inspect existing head/tail silence before adding breath, without automatically trimming speech or treating silence detection as listening approval.

Record the resulting change in the current plan. If text, evidence or a substantive picture decision changes, refresh the applicable existing review/receipt; do not copy an old pass onto the new subject. Only changed authorized lines need new synthesis, and failed attempts still consume the agreed budget. Nothing here expands paid-call permissions or overrides a no-synthesis/no-editing task boundary. If a concrete conflict remains after the bounded repair, return it once with the affected unit/line, measured gap and needed decision rather than starting another generic "improve it" loop.

### Executable handoff

Use the existing execution brief and current project artifacts, not a new schema. Give the editor:

- Target project/sequence and creator stage; blueprint/current-copy/current-picture-plan revisions; permitted changes and preserved content. If the editor cannot read the planner's local document, supply its actual relevant content through supported input, not only a desktop path.
- For each selected unit/point and phrase/beat: actual source asset/frame IDs and ranges, original playback versus explanation/revisit, what viewers should understand, chosen composition/transition/annotation, and what remains visible while the line is spoken. Source clocks and output clocks stay distinct.
- Exact reviewed narration/captions/labels; real audio asset IDs and measured durations where available; reconciled output placement, breath and transition intervals. Rough discovery ranges and hypothetical speech rates are not verified cut points or final timing.
- Concrete tool edits or an unambiguous placement/geometry specification that existing tools can implement, plus readback/preview checks for the changed section. The executor may calculate frame rounding and other implementation details within these decisions; it may not silently delete a point, change the copy or choose a new teaching approach.

Keep this handoff linked to the project-owned selected-task baseline and current plans. Supplied planner/operator decisions are recorded as supplied, not claimed as autonomous editor discoveries. Blueprint changes are planned work, not an already executed timeline. These are workflow requirements; the existing structural/receipt gates do not automatically prove creative quality or enforce measured-audio fit.

## Input brief

Record product name; original-video reference; destination language and creator stage (`new_contact` or `existing_partner`); optional supplied analysis emphasis; product/cooperation imagery; performance screenshot and its period/metric; approved voice and existing audio; and any approved project to revise.

References may be current media IDs, attachments or user-supplied local paths. A path in a document does not mean the media has been imported or inspected. Resolve each reference through available import/read tools and retain the resulting asset ID. Mark missing optional data explicitly; do not invent opening performance numbers or cooperation terms. If creator stage is unknown, complete the common-body plan and ask before finalizing its CTA.

Local media import and local document reading are different capabilities. If the current editor can import media paths but cannot read local JSON/Markdown/PDF text, use supplied chat text or parsed attachments for the brief and reference documents. Do not keep searching for a filesystem reader after its absence is established. Explain the specific missing input and continue any work supported by already supplied content; never claim a path was read merely because it was listed.

In the browser editor, a desktop-only local-path import tool does not make local files accessible. Use media-pool uploads for browser assets; after an explicit unsupported-tool result, do not retry that path or claim the asset exists.

## Evidence and product understanding

Use short evidence IDs. Each entry records source asset, source time range/time base, evidence kind (`original_claim`, `visible_action`, `analyst_interpretation`), content and inspection basis. Interpretations link to their supporting evidence IDs; they do not replace the source claim or visible action. A historical approved description is a reference, not a fresh observation.

Keep inspection limits in internal review notes. Creator-facing narration explains what the creator does and how that makes a buying reason easier to understand; do not automatically turn notes such as "not a temperature test" into narration or labels. If a sentence overclaims, narrow it to the observed expression rather than append a product-testing disclaimer. This does not authorize hiding a material uncertainty or repeating an unsupported promise.

Build this compact map:

| point_id | Buying reason / selling point | Original wording and numbers | Visible expression and evidence IDs | Why worth explaining | Planned coverage |
| --- | --- | --- | --- | --- | --- |

List the complete source's functional sequence, then choose coherent explanation units. Required product information may be conveyed by narration or prominent text; record which, so a visual-only 30W label is not reported as spoken.

## Selected-point baseline and explanation units

Product implementation: persist this checklist as `clipMentorAnalysis.source_breakdown`, using the [source breakdown contract](pre-edit-analysis.md#source-breakdown-contract). `analysis.points` retains analysis findings; `source_breakdown.points` selects the teaching tasks that must survive downstream revisions. Do not create another selected-task list from a shortened manuscript. The existing analysis tool reports structural coverage and actual source-range bindings, and the production gate requires a registered plan plus a matching independent review. Semantic quality, continuous viewing and manual UI export are not certified by these checks.

Use the coverage map above as one versioned checklist, not a second parallel analysis report. The author agent establishes it in the first analysis round from buying reasons → visible signals → how the source expresses them, with priorities, necessary filming conditions, evidence/source ranges and relevant operator feedback. This explains persuasion, not independently proven product efficacy. Do not require advance human approval by default; reuse already supplied decisions. Preserve this baseline before compression or localization rather than substituting the latest shorter draft. Do not treat every observed action as a mandatory point.

Each unit binds original playback and explanation together:

| Original playback source range(s) | Selected point IDs and required meaning | Product value / why worth learning | Explanation picture source range(s) | Picture-only content and why its teaching value is understandable without explanation |
| --- | --- | --- | --- | --- |

After each shortening, deduplication, translation or locking round, account for every selected point as retained, merged or removed. Unchanged IDs can be listed together; expand only changes, preserving the baseline rather than replacing it with the shortened draft.

| Point ID | Retain / merge / remove | Current unit and explanation landing | Reason and assumptions | Reviewer decision / unresolved issue |
| --- | --- | --- | --- | --- |

- A merge names the destination and preserves required meaning and filming conditions. Dropping a required condition or downgrading an explained point to an unexplained appearance is a substantive change, even if labeled a merge.
- Removing a selected point requires a recorded reason and named independent review agent's decision, not a default human signature. The author cannot silently approve its own removal. An explicit user-mandated point cannot be waived against that instruction without the user's decision. Unsupported claims remain withheld: retain the affected point as unresolved rather than repeat the claim or erase the gap.
- Selected teaching points default to an explanation of why the method matters, not just a replay. A short meaningful label may share that role; picture-only treatment needs an explicit reason why creators can understand the value without explanation. "Already appeared in original playback" only supports avoiding redundant replay, not automatically omitting interpretation.
- Insufficient duration triggers reprioritization of screen time/presentation and removal of redundant wording, not silent loss of selected meaning. Do not preserve an old short window at the expense of a point.
- A substantive change to any unit column requires a new review, even when only the original playback range changed and narration stayed identical. The registered contract is included in the production receipt digest; tool revisions increment the revision, so restoring old content does not revive approval. The current conservative gate invalidates the full copy receipt, not an independently authenticated per-unit approval. Reuse unchanged evidence when reviewing again.
- Review both local correspondence and the unit relationship: does the explanation unpack what viewers just saw? A deliberate earlier-stage replay is allowed if viewers can understand what is being revisited and why. Source time need not always increase, but usage and comparison stages cannot be silently interchanged.

Keep the selected-task checklist and unit plan in the project contract and hand off its actual content/version through the analysis tools. A desktop Markdown path alone is not delivery to the editor Agent. Existing historical documents remain provenance, not the current execution plan. This checklist protects selected content; it does not prove that analysis found every valuable point.

Separate deterministic and semantic checks. Code can require every baseline ID to have an existing explanation landing or explicit removal record and detect changed units. A removal reason's presence, a valid reference or an unchanged ID does not establish adequate meaning or justify the removal. In particular, an explicit picture-only downgrade can pass structural accounting yet fail L1. Structural success must never approve a complete film.

For independent L1/L2 review, start a fresh review agent only within the authorized model-call budget. Give it source timeline/evidence access, the original point checklist (including product value and uncertainty) and the current narration/picture mapping. Exclude the author's justifications, self-review verdict and previous review answers; the reviewer needs the content it is judging, not the author's defense. It returns per-point/unit L1/L2 pass / needs_revision / insufficient_evidence with evidence references and concrete gaps, not a new script. Text-only review cannot claim continuous viewing or listening. Return failures to the author for bounded repair before asking the operator to inspect a candidate; do not add indefinite agent loops or new providers. Record the authorized round cap and stop as unpassed if exhausted.

For L2, inspect each unit's original-playback evidence before its explanation evidence, in output order. Record the visible original content before opening the paired explanation, then compare: what was shown; what is explained; what is the same, added or revisited; and which actual words, composition or visual transition establish the relationship. A pass cites evidence from both sides, not only a coherent sequence of explanation frames. Do not require a particular rewind phrase or reject every earlier-source replay. Separate judgment of visible/textual continuity from unverified motion/audio continuity: missing material limits the affected judgment to insufficient_evidence, not an assumed pass or automatic failure of everything. Preserve the actual inspection order and evidence limits; do not rewrite a reviewer verdict to match an expected outcome.

## Internal editing blueprint

For each unit record:

- `unit_id`, `point_ids`, purpose and required information in its logical order.
- Original playback range(s), original speech meaning, visual actions and complete-sentence/action boundary checks.
- Each explanation line: `line_id`, Chinese intent, localized text, linked evidence IDs, what the viewer sees, why it supports the line, and any specific on-screen label.
- Timing basis: planned budget versus actual existing/generated audio duration; source and output ranges remain separate. Reconcile actual audio before final placement.
- Composition/annotation intent, source frame or range, target and coordinate space. Coordinates may be unresolved during planning, but cannot be treated as verified before placement.
- Asset references, supplementary-material purpose if any, unresolved observations and the next concrete action.

Preserve a group's whole argument; do not generate a separate transition for each point or sentence. Storyboard for creators is a separate three-column account of the original video.

Complete information does not require replaying every source second. Retain coherent speech/actions for selected points, trim redundant detail only at verified boundaries, and keep secondary points and the source CTA proportionate. Before handoff, sum the proposed duration and identify any long explanation with too little visual information; shorten redundant wording or redistribute the budget without dropping selected meaning, rather than stretching the footage. Include the one-time invitation into the breakdown after performance context. Write production notes in the user's requested language and localize only viewer-facing copy.

Assess the source closing's purchase function, not just product recognition: grouped goods, any supported offer and the purchase cue may work together. An ordinary consumer CTA needs only a brief explanation; do not give it the core demonstrations' weight. Unconfirmed price or bundle details restrict specific claims, not the supported purchase invitation itself. Keep this source consumer CTA distinct from our creator cooperation CTA.

The complete-video budget must include original playback, narration, breath/transition intervals, opening and creator CTA. A narration-only sum is not a complete-video budget. Distinguish measured reused audio from text estimates and account explicitly for any original-audio range that extends beyond its picture range.

When revising an approved case, prefer its approved localized sentences and available voice files over rewriting every line. Do not drift from “the creator uses touch to show that the phone is not hot” to “it does not heat quickly” or temperature measurement. Keep specific accepted annotations. Extra product footage is not automatically relevant evidence: an interface close-up cannot illustrate night-time worry or a touch gesture merely because it is the same product.

## Malay narration and on-screen microcopy

Help busy Malaysian creators understand how the original creator expresses a product's buying reasons and feel ready to try their own version. Narrate an observed example and explain its value; do not turn the body into filming commands addressed to the viewer, product sales patter, or criticism of their existing work. A light invitation to notice a detail is possible; do not force every sentence to start with `Dia`.

- **Keep the group's argument.** Across each explanation unit, connect the buying reason, specific filming choice and why it helps viewers understand. Merely naming actions or generic techniques such as "visual trust" is insufficient. Product fit does not require a unique feature or independent efficacy proof; an ordinary filming method can still express this product's buying concern. Once the purpose is clear, another sentence may add a condition or stage without repeating the whole argument. Keep ordinary source CTA material brief without erasing its purchase-invitation function.
- **Do not confuse restraint with abstraction.** Factual safety is necessary, not sufficient. Internal categories such as "makes the topic clearer", "adds an experiential dimension" or "distinguishes stages" cannot stand in for the concrete body part, comparison, contact or display relationship and what it lets a buyer see or judge about this product. Keep internal analytical notes separate from viewer-facing meaning; review the Malay line and its Chinese meaning together instead of polishing only the translation. Evaluate the whole unit, not a banned-word list or a required pronoun/formula in every sentence.
- **Explain buying relevance without inventing the buyer's response.** An observed choice may make a concern tangible, suggest a use experience or help comparison; it does not establish pleasant scent, premium quality, complete washing, treatment identities, proven efficacy, satisfaction, trust gained or higher conversion. Preserve useful interpretation rather than retreat to empty labels or add disclaimers. Before synthesis, ask whether a creator can identify the learnable filming relationship and its relevance to this product. If not, return the affected unit as needs_revision even when facts, IDs and caption text match. Audit a lively rewrite for unsupported promises and psychological or sales causation; do not add a model call or consumer experiment by default.
- **Preserve material filming conditions.** Identify the action, object, stage/timing, camera direction/distance, comparison arrangement and necessary continuity from the evidence. Retain conditions needed to understand the method when shortening, translating or changing tone. Narration, specific labels and visible composition can share this information, but record where each condition is conveyed; an attached evidence ID or a shot merely existing does not prove coverage. Do not replace a meaningful stage with a vague "then", or omit camera proximity/side-by-side placement to sound smoother. Do not force all possible conditions into every sentence.
- **Write speakable copy.** Remove repetition and roundabout clauses before cutting information. Shorter is not automatically better, and word count is not measured speech duration. Everyday contractions and small amounts of English may fit; do not force slang or assume all creators understand jargon. Words such as `kenalkan`, `hasil` or `mimik muka` are not individually banned or proof of an overclaim. Judge the whole sentence, evidence and local feedback.
- **Keep meaning and scope consistent.** Chinese review meanings and Malay copy may differ in syntax, not in entity, quantity/scope, stage, promise or purchase action. Clarify a vague object without inventing "all products" or a bundle. Keep original claims, visible actions and analyst interpretations separate. No unsupported side identities/Before-After, instant-effect or safety promises, superlatives, retention gains or sales causation. Internal limitations do not automatically belong in creator-facing narration.
- **Preserve core facts.** Keep source-supported core selling points and key numbers, including units, entity, period and approximation. A 30W label must not disappear into "fast"; a touch gesture is not a temperature measurement or zero-heat proof. Do not inflate offers, commissions, earnings or cooperation terms for energy or colloquial tone.
- **Separate text surfaces.** Synchronized captions use the same approved words as narration, with line wrapping rather than a second shortened script. Keep verb phrases, negation and number/unit relationships intact when wrapping; wrapping, caption-card timing and spoken boundaries require separate checks. Prefer short auxiliary labels, using four words or fewer as an editing reference rather than a hard gate; preserve necessary meaning and check actual readability against size and screen time. Labels describe the current action/state/selling-point relationship, not generic method names. The word-count reference does not apply to captions, source burned-in text or product proper names. Labels need their own evidence and correct appearance time; they cannot add promises or a purchase route absent from the verified meaning.
- **Resolve relevant source uncertainty.** Garbled ASR is not a verbatim quote. Separate operator-supplied intent from independently checked source words; a faithful paraphrase need not use the identical verb, but cannot invent an exact action/route. When uncertain source wording or a purchase path affects the line, verify the source speech first. Respect any task-specific pre-synthesis listening requirement even if copy is generalized; do not claim a documented check is an automatic editor gate.
- **Keep the two CTAs distinct.** Explain the source creator's consumer purchase invitation as part of the original video's method, rather than instructing breakdown viewers to buy. Our creator CTA depends on stage: new contacts need the product, confirmed benefits and available filming support linked to contact; existing partners need confidence to film in their own style. No invented samples, deadlines, scarcity, trend windows or guaranteed earnings.
- **Use actual voice and picture checks.** Before synthesis, review intent, required conditions, evidence, copy, caption/label meaning and planned budget together. After authorized synthesis, measure actual speech and pauses and inspect the corresponding picture. A longer rewrite does not inherit old slots. Shorten without dropping key information, or identify authorized local timing changes; never rush, cut speech, slow footage or hold empty pictures to fit. Native review, actual listening, visual review and technical checks remain distinct.
- **Review conservatively.** Separate necessary factual/coverage corrections, stylistic tradeoffs and judgments needing local/audio review. Preserve correct text; edited-line count is not failed-line count or proof that a new draft wins. Inspect the actual prompt/input before attributing failure to a model; supplied facts are not independent discoveries. Do not infer general model quality from one unequal first-draft-versus-revision comparison or add calls to hunt for a preferred answer. If comparing variants, use per-line anonymous choices, allow ties/both-needing-work, and label text-only judgments honestly; authorized audio comparisons use consistent voice/speed and picture conditions.

For writing, hand off meaning rather than analytical wording. For each unit, pass the required buying concern and learning outcome, source-backed actions with IDs/ranges, necessary filming conditions, and unresolved claims separately from internal analysis and old drafts. Preserve those constraints, not the analyst's sentence structure or category names. Write the creator-facing narration afresh; its Chinese review meaning must describe what that narration actually says, not make a vague Malay line sound more concrete. Keep existing unit/point/line links and budget provenance, with synchronized captions and separately evidenced short labels. A copy-revision task may replace candidate wording; it does not authorize changing approved audio or media.

Supplied examples and fluency judgments are candidates, not native approval or synthesis/export authorization. Model routing and specific sample sentences/durations are task decisions, not permanent writing rules. New guidance does not authorize regenerating approved audio, changing `Video asal` styling or adding effects.

Before returning a candidate, read only the proposed narration, captions/labels and stated picture plan as the creator would receive them. In the existing review record, identify the concrete method and product-related understanding actually communicated, citing the words or visible relationship that convey it. Then compare that understanding with the required meaning and filming conditions. Do not fill a gap with the author's internal explanation or evidence IDs. A shorter sentence that still only names an analytical category has not resolved the problem. Return specific failed meanings to the writer without supplying replacement lines; preserve wording that already works. This is a writing/review step, not a new mandatory model call, fixed sentence formula or automated semantic gate.

## Handoff and revision

At handoff identify the target project/sequence, approved blueprint revision, media IDs and editable item mapping for each unit/line/label. Read the current project before applying it; never overwrite manual changes from an old snapshot. Record open uncertainties and completed checks without inventing a numeric quality score.

Include the current point checklist/version, changed dispositions and unit review states. Each inherited substantive decision travels with its reason, evidence and assumptions; if an assumption no longer holds, reopen the decision rather than repeat its conclusion. Copy approval does not establish unit coverage or authorize an unapproved removal. Missing checklist content or a pending substantive change must be reported before locking the affected unit for production.

For existing approved work, resolve the requested change against these actual item IDs, read back the new properties and compare unaffected items. Run only checks relevant to the changed portion and its dependencies, retaining the full project's known unresolved checks.
